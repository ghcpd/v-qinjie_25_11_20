🧭 Vulnerabilities included (insecure/)
I intentionally embedded the following vulnerabilities into insecure:

1. Hardcoded API key in client JS
   - page.js: HARD_CODED_API_KEY
   - Symptoms: Key shows up in UI and client script; can be read from source.

2. Client-side key leak and tokens in query string
   - page.js: fetch call sends ?apikey= in the URL (exposes key via logs, referer).
   - route.js returns `received_key` and logs it.

3. XSS vulnerabilities / unsafe DOM insertion
   - page.js: uses `el.innerHTML = message;` to render raw content (reflected XSS).
   - Symptoms: Input like `<img src=x onerror=window.__XSS_EXECUTION=true>` will execute.

4. Insecure use of exposed admin secret / lack of access control
   - Admin secret shown on page
   - page.js reveals `ADM_SECRET_CLIENT_VISIBLE_ABC` to any visitor.

5. Sensitive data leaks in logs / debug prints
   - route.js console.logs API keys and returns the received key (so logs and response leak the secrets).

6. Unsafe fetch behavior / insecure fetch endpoints
   - Fetch uses query parameters and not server-handled secrets.

🔒 Fixes in secure/
I fixed the above issues in secure with these changes:
- No client-side secrets:
  - Removed hard-coded API keys from client; use server-only `SECURE_API_KEY` via environment variables (server code uses `process.env.SECURE_API_KEY`).
- No secrets in URL / server-only fetch:
  - Client posts to `/api/echo` using POST body and the server uses the server-side secret without exposing it.
- Input Validation & Sanitization:
  - Server uses `sanitize-html` in route.js to strip dangerous tags/attributes.
  - No usage of `innerHTML` or `dangerouslySetInnerHTML` for rendering untrusted input.
- Remove sensitive logs:
  - Server logs only benign events (not secrets).
- Access control for admin:
  - secure admin uses server-side cookie-based session (HttpOnly cookie) and redacts admin secret in the UI.
- Secure patterns & Next.js best practices:
  - Use environment variables for secrets, server-side API routes to hold secrets, minimal server-side logic to protect sensitive data.
